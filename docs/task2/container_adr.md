| **№** | **Действующие лица или системы**                            | **Use Case**                              | **Описание**                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
|:-----:|:------------------------------------------------------------|:------------------------------------------|:------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
|   1   | Дежурный, Зоотехник, Директор хозяйства, Веб-портал, Мобильное приложение | Просмотр живого видеопотока через UI | 1. UI обращается в `apiGateway`.<br/>2. `apiGateway` маршрутизирует в `coreApi`.<br/>3. `coreApi` запрашивает метаданные камер у `videoIngest`.<br/>4. `coreApi` возвращает список доступных камер.<br/>5. UI запрашивает видеопоток конкретной камеры.<br/>6. UI получает ссылку на медиапоток и транслирует видео. |
|   2   | AI-трекинг (внешняя система), `aiAdapter`, `coreApi`, Дежурный | Реагирование на инцидент с животным | 1. `videoIngest` публикует кадры в `rabbitMQ`.<br/>2. `aiAdapter` читает кадры из `rabbitMQ`.<br/>3. `aiAdapter` отправляет кадры в `aiTracking` (gRPC).<br/>4. `aiTracking` возвращает результат в `aiAdapter`.<br/>5. `aiAdapter` публикует событие в `rabbitMQ`.<br/>6. `notifications` читает событие, формирует уведомление.<br/>7. `notifications` отправляет через `notificationProvider`.<br/>8. Дежурный получает уведомление, открывает карточку события в UI.<br/>9. UI обращается в `coreApi` за деталями события.<br/>10. `coreApi` читает из `dataWarehouse` и возвращает данные. |
|   3   | BI-Аналитик, `biSystem`, `dataWarehouse` | Отчётность по безопасности и благополучию | 1. Аналитик открывает BI-систему.<br/>2. Выбирает шаблон отчёта.<br/>3. Настраивает период и срезы.<br/>4. BI-система читает данные из `dataWarehouse` (SQL/ODBC).<br/>5. Строит дашборд: инциденты, реакция, благополучие.<br/>6. Делится с руководством. |
|   4   | BI-Аналитик, `biSystem`, `moduleAnalytic`, `dataWarehouse` | Анализ инцидентов с животными | 1. Аналитик открывает дашборд инцидентов.<br/>2. Выбирает период, ферму, секцию.<br/>3. Смотрит разбивку по типам событий.<br/>4. `moduleAnalytic` агрегирует данные из `dataLake` и пишет в `dataWarehouse`.<br/>5. Аналитик выявляет тренды и пики.<br/>6. Формирует отчёт с рекомендациями. |
|   5   | Директор хозяйства, `coreApi`, `erpSystem` | Просмотр финансовых отчётов | 1. Директор открывает веб-портал.<br/>2. Запрашивает отчёт по финансам.<br/>3. UI обращается в `apiGateway`.<br/>4. `apiGateway` маршрутизирует в `coreApi`.<br/>5. `coreApi` через `erpSystemClient` запрашивает данные у `erpSystem`.<br/>6. `coreApi` возвращает отчёт в UI. |

### <a name="_u8xz25hbrgql"></a>**Нефункциональные требования**

| **№** | **Требование**                                                            |
|:-----:|:--------------------------------------------------------------------------|
|   1   | Система мониторинга должна обеспечивать высокую отказоустойчивость 95,95% |
|   2   | Система должна позволять добавлять новый функционал без изменения существующего |
|   3   | От момента фиксации нештатной ситуации видеоаналитикой до оповещения дежурного — не более 5 секунд |
|   4   | Система видеоаналитики должна обрабатывать видеопоток в реальном времени с задержкой в миллисекундах |
|   5   | Один центральный сервер + edge-устройства на каждой ферме |
|   6   | Нестабильный WiFi → обязателен резервный канал 4G/LTE |

**Недостатки, ограничения, риски**

| **№** | **Решение**                                                       | **Недостатки**                                                                    | **Ограничения**                                                               | **Риски**                                                                                                                                                                        |
|:-----:|:------------------------------------------------------------------|:----------------------------------------------------------------------------------|:------------------------------------------------------------------------------|:---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
|   1   | `coreApi` (Java, Spring Boot)                                     | God Object при росте числа сценариев                                              | Зависит от `dataWarehouse`, `videoIngest`, `erpSystem`                        | При падении `coreApi` — UI недоступен                                                                                                                                            |
|   2   | `aiAdapter` (Go)                                                  | Задержка при gRPC-стриме                                                          | Зависит от внешнего `aiTracking`                                              | При недоступности AI — события не формируются                                                                                                                                    |
|   3   | `notifications` (Node.js)                                         | Смешение ролей (правила + доставка)                                               | Зависит от `rabbitMQ` и `notificationProvider`                                | При падении `notificationProvider` — уведомления уходят в DLQ                                                                                                                    |
|   4   | `rabbitMQ`                                                        | Единая точка отказа                                                               | Пропускная способность                                                        | При перегрузке — потеря событий (митигация: DLQ)                                                                                                                                 |
|   5   | `dataWarehouse` (ClickHouse)                                      | Не подходит для транзакционных запросов                                           | Оперативные запросы медленнее                                                 | При отказе — UI не работает                                                                                                                                                      |
|   6   | `dataLake` (MinIO S3)                                             | Дорогое хранение больших объёмов                                                  | Пропускная способность S3                                                     | При отказе — видео не сохраняется                                                                                                                                                |
|   7   | `videoIngest` (Go)                                                | Зависит от стабильности сети камер                                                | Пропускная способность RTSP                                                   | При отказе камер — нет видеопотока                                                                                                                                               |
|   8   | Edge-обработка (гибрид edge + cloud)                              | Сложнее в разработке и поддержке                                                  | Нужен edge-деплой на каждой ферме                                             | При отказе edge — локальные сценарии не работают                                                                                                                                 |
